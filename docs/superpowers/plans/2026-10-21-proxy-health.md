# 代理质量筛选实施计划

目标：把已确认的真实请求检测、重复采样、失败过滤接入现有订阅更新；保持原订阅 URL。

设计：新增 scripts/health_check.py，使用系统 curl 按节点协议代理真实 HTTPS 请求。每节点两个目标、三轮、六次全通过，平均耗时不超过 2.5 秒；再下载精确 256 KiB，平均至少 64 KiB/s。保留目标及代理证书校验，不自动关闭证书验证。最多 8 个节点并行，不依赖端口开放结果。按通过节点的平均延迟排序。

生成器先完成筛选，再更新配置和源快照。失败全部过滤时保存本轮报告，但保留上一份配置与快照并非零退出。Actions 每轮上传报告，在成功更新时将 health-check.json 一起保存。检测以运行机器的网络为准，不承诺长期可用。

实施步骤：

- [x] 实现 health_check.py，接入 update_subscription.py 的默认路径；无跳过检测开关。
- [x] 工作流增加检测脚本触发、报告上传与保存；README 写清筛选阈值及空结果行为。
- [x] 运行临时验证、当前线上地址的真实检测和 YAML 校验；删除临时文件。
- [ ] 沿用用户已授权的订阅发布工作流，以中文提交并推送，验证 GitHub Actions 和最终 Raw 配置。

验证记录：9 项临时验证通过，包括真实 curl 连接本地认证代理返回 407、全部过滤后保留旧订阅、源文件失败时生成本轮失败报告、Windows curl 本地编码错误信息。两轮真实列表检测分别通过 2 个和 1 个节点；最新配置仅保留通过六次 HTTPS 请求及下载阈值的节点。配置、工作流语法与分组引用均已检查。独立审查发现的旧报告上传问题已修复。
